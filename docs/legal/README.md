## 三、登录同意流程（实现规格）

### 3.1 交互稿

```
┌──────────────────────────────────────┐
│  登录 9友地图                          │
│                                      │
│  邮箱  [ you@example.com          ]   │
│  验证码 [ 123456 ]      [获取验证码]   │
│                                      │
│  渠道服  [ 请选择 ▾ ]   ← 必选，影响能否加好友
│  城市    [ 请选择 ▾ ]   ← 必选，用于界面天气
│                                      │
│  ────────────────────────────────    │
│  ☐ 我已阅读并同意《用户协议》《隐私政策》 │
│    《个人信息收集与用途清单》《免责声明》 │
│    《社区规范》                        │
│  ☐ 我同意在公开地图上展示我选择的位置    │
│    （默认模糊至约 500 米，可随时关闭）   │
│  ☐ 我同意向同服用户展示我的游戏 UID     │
│    （可选，随时可关）                  │
│  ☐ 我确认我已年满 14 周岁              │
│  ────────────────────────────────    │
│        [ 登录 / 注册 ]  （未勾选必要项时置灰）│
│                                      │
│  或者先  [ 随便看看 ]  ← 游客只读       │
└──────────────────────────────────────┘
```

规则：

1. **第 1、4 项必须勾选**才能提交；第 2、3 项可拒绝（拒绝第 2 项则不能放标记）。
2. 所有勾选框**默认不勾选**，不得预选。
3. 文件名必须可点击，**在当前页以抽屉/弹层打开全文**（不要跳走，避免用户丢失输入）。
4. 提交时若未勾选必要项：按钮置灰 + 点击时 toast「请先阅读并同意《用户协议》与《隐私政策》」。
5. 游客（未登录）可浏览地图、看聚合人数、看天气；**不能放标记、不能互动**。

### 3.2 文案（可直接用）

- 顶部小字：`登录即表示你已阅读并同意以下条款；我们会严格按《个人信息收集与用途清单》处理你的信息。`
- 位置项副文案：`坐标默认模糊至约 500 米。请不要把标记放在住所或学校。`
- UID 项副文案：`只有同一渠道服的人能看到，随时可以关掉。`
- 年龄项副文案：`本服务不向未满 14 周岁的用户开放。`
- 底部：`我们不会索要你的游戏账号密码，也不会在后台读取你的定位。`

### 3.3 服务端校验（关键，不能被前端绕过）

```ts
// 伪代码：注册/登录必过
const REQUIRED = ['terms', 'privacy', 'age14'] as const;

async function signup(req: SignupReq) {
  const c = req.consents ?? {};
  for (const k of REQUIRED) {
    if (c[k] !== true) throw new ApiError(428, 'CONSENT_REQUIRED', k);
  }
  // 位置同意是「放标记」的前置条件，不是注册的前置条件
  await db.tx(async (t) => {
    const user = await t.insertUser(req);
    for (const [type, agreed] of Object.entries(c)) {
      await t.insertConsent({
        userId: user.id, type, version: CURRENT_DOC_VERSION[type],
        docHash: DOC_HASH[type], action: agreed ? 'agree' : 'withdraw',
        ip: req.ip, ua: req.ua,
      });
    }
  });
}

// 任何写操作前统一检查（放标记、发波、递伞、改名片）
async function requireConsent(userId: string, type: ConsentType) {
  const ok = await db.hasConsent(userId, type, CURRENT_DOC_VERSION[type]);
  if (!ok) throw new ApiError(428, 'RECONSENT_REQUIRED', type);
}
```

### 3.4 条款版本与重新同意

- 每份文件有 `doc_type` + `version` + 文本 `sha256`。
- 登录与每次关键操作都会比对当前版本；版本不一致 → 返回 `428 RECONSENT_REQUIRED` → 前端弹「条款已更新」弹窗，**只展示变更摘要 + 全文链接**，重新勾选后才可继续。
- 只要求重新同意**发生变更**的那一份，不要一次性把五份都弹一遍。
- 用户可拒绝：拒绝则**保留只读浏览**，但标记、互动、名片编辑全部锁定。

### 3.5 撤回同意

| 撤回项 | 系统行为 |
|---|---|
| 位置展示 | 所有标记立即下架（不删除），地图上不再出现你 |
| UID 展示 | 同服用户立即看不到 UID |
| 全部同意（即注销） | 走注销流程：15 日内删除或匿名化 |

### 3.6 记录表（与清单附表 4 对应）

```sql
CREATE TABLE consents (
  id          INTEGER PRIMARY KEY,
  user_id     TEXT NOT NULL,
  doc_type    TEXT NOT NULL,   -- terms|privacy|location|uid|age14
  doc_version TEXT NOT NULL,
  doc_hash    TEXT NOT NULL,
  action      TEXT NOT NULL,   -- agree|withdraw
  ip          TEXT,
  ua          TEXT,
  created_at  TEXT NOT NULL
);
CREATE INDEX idx_consents_user ON consents(user_id, doc_type, created_at);
```

### 3.7 测试用例（上线前必须过）

- [ ] 未勾选任何项 → 按钮置灰，点击有提示
- [ ] 只勾第 1 项、不勾年龄 → 拒绝提交
- [ ] 只勾第 1、4 项、拒绝位置 → 注册成功，但放标记返回 `428`
- [ ] 拒绝 UID → 同服用户查不到 UID
- [ ] 直接调接口伪造 `consents` → 服务端仍按真实请求判断
- [ ] 修改远端条款版本 → 老用户下次操作收到 `428`，重签后可继续
- [ ] 撤回位置同意 → 点位从地图消失，但数据未被删除
- [ ] 注销 → 15 天内数据库无残留（除日志与同意记录）
- [ ] 游客访问 → 可看地图，写操作全部 401
