# 9友地图 · 部署与上线清单

> 目标：把一个本地跑通的 `node server/index.js`（Node 24 + SQLite + 零依赖）变成公网可访问的站点。
> 全程约 1–3 小时（不含备案等待）。

---

## 0. 先做决定：放境内还是境外

| | 境内（大陆机房） | 境外 / 香港 |
|---|---|---|
| **ICP 备案** | **必须**，个人备案 7–20 天，期间网站不能对外提供内容 | 不需要 |
| 访问速度 | 快 | 一般（香港尚可） |
| 成本 | 轻量 2C2G 约 ¥60–90/月 | 轻量 2C2G 约 ¥24–40/月 |
| 后续接入短信 / 支付 | 可以 | 基本不行 |
| 合规态度 | 最稳 | 仍需遵守国内内容法规，只是省了备案 |

**建议**：先在香港/境外把站跑起来验证，同时并行提交备案；备案下来再迁回大陆。
> 注意：港口不是法外之地，内容合规、隐私政策、举报机制一样要做。

---

## 0.5 更省钱的方案（含免费额度）

> 先把结论说清楚：**这个站不能直接部署到 GitHub Pages。**
> Pages 只托管静态文件，而这个站需要：服务端接口、数据库（SQLite）、登录会话、管理后台。
> 静态托管能放 `public/`，但 `/api/*` 全部无法工作。

GitHub 的正确用法是**当代码仓库 + CI**（push 自动部署到下面任一目标），而不是当运行环境。

| 方案 | 月成本 | 改动量 | 说明 |
|---|---|---|---|
| **A. 免费云主机**（Oracle 永久免费 / 学生机 / 新用户特价） | **¥0–99/年** | **0** | 代码原样跑，最省事 |
| **B. Cloudflare Pages + D1 + Workers** | **¥0**（免费额度） | 需要移植（约 600–900 行） | 全球 CDN、免运维、天然抗打 |
| **C. 家里电脑 / NAS + Cloudflare Tunnel** | ¥0 | 0 | 依赖你的机器常开、家宽上行 |
| **D. GitHub Pages + Supabase** | ¥0 | 需要重写后端 | 纯前端方案，国内访问与数据出境有风险 |

### A. 免费云主机（推荐先走这条）

- **Oracle Cloud Always Free**：ARM 4 核 / 24GB 内存 / 200GB 盘，永久免费（需信用卡验证，热门区域常无库存）
- **阿里云 / 腾讯云 学生机**：约 ¥9–10/月
- **阿里云 99 元/年**、腾讯云轻量新用户首年特价：2C2G 足够本站在几百人日活下运行
- 缺点：境内机房要备案；境外区域国内访问一般

跟本文第 1–7 节步骤完全一致，**代码一行不用改**。

### B. Cloudflare 免费额度（长期最优）

| 资源 | 免费额度（以官网为准） |
|---|---|
| Pages 静态请求 | 不限量 |
| Workers 请求 | 10 万次/天 |
| D1 数据库 | 5GB 存储、500 万行读/天 |
| 出站流量 | 不限量 |

对本站（几百到几千日活）绰绰有余。代价是要把代码移植到 Workers 运行时：

- `node:sqlite` → **D1**（SQL 基本兼容，API 变异步）
- `node:http` 的 req/res → **Request/Response**
- `node:fs`（regions.json、法律文本）→ 打包成模块导入
- SSE → 改成轮询（30 秒一次），或上 Durable Objects
- session 的 HMAC、验证码的哈希 → **WebCrypto**（都支持，没有 scrypt 但我们本来也不存密码）

**这块工作我可以帮你做**，做完就是永久免费 + 全球 CDN。

### C. 家里电脑 + Cloudflare Tunnel

```bash
# 家里机器上
cloudflared tunnel --url http://127.0.0.1:3000
```

得到一个 `https://xxx.trycloudflare.com` 临时地址；绑定自己的域名需要 Cloudflare 账号 + 托管域名。
优点：0 成本、代码不改。缺点：断电断网就挂、家宽上行有限、电脑不能休眠。

### D. 为什么不太推荐 GitHub Pages + Supabase

- 需要把 Node 后端整体换成 Supabase（Postgres + Auth + Realtime + RLS），相当于重写
- Supabase 是境外服务，**用户数据出境**，与《个人信息保护法》冲突，隐私政策要额外说明并单独同意
- 国内访问不稳定

## 1. 服务器准备

以 Ubuntu 24.04 为例：

```bash
# 创建专用用户（不要用 root 跑服务）
sudo adduser --system --group --home /opt/jiuyoumap jiuyoumap

# 基础软件
sudo apt update && sudo apt install -y caddy ufw
sudo ufw allow 22,80,443/tcp && sudo ufw --force enable

# Node 24（用官方二进制，避免 NodeSource 源的问题）
curl -fsSL https://nodejs.org/dist/latest-v24.x/SHASUMS256.txt -o /tmp/sums
# 或者更省事：用 nvm
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.1/install.sh | bash
# 安装完后
nvm install 24 && nvm alias default 24
node -v   # 应显示 v24.x
```

## 2. 上传代码

```bash
# 方式一：git（推荐，方便滚动更新）
sudo -u jiuyoumap git clone <你的仓库> /opt/jiuyoumap
# 方式二：本地 rsync
rsync -av --exclude data --exclude node_modules ./ user@server:/opt/jiuyoumap/
```

**不要把 `data/`（数据库、session.key）和 `data/local.json`（天地图 Key）提交到仓库**——`.gitignore` 里已经排除。

---

## 3. 环境变量

创建 `/etc/jiuyoumap.env`，权限 600、属主 root：

```bash
sudo tee /etc/jiuyoumap.env >/dev/null <<'EOF'
# ── 站点 ──
HOST=127.0.0.1
PORT=3000
NODE_ENV=production

# 天地图 Key（浏览器端，必须配，否则没有底图）
TDT_TK=你的天地图Key

# 会话签名密钥：openssl rand -hex 32
SESSION_SECRET=换成随机长串

# 第一个管理员（注册过的邮箱），启动时自动提为站长
ADMIN_EMAIL=你的邮箱@example.com

# ── 邮件（必须配，否则验证码不会真的发出去）──
SMTP_HOST=smtp.qq.com
SMTP_PORT=465
SMTP_USER=你的邮箱@qq.com
SMTP_PASS=邮箱授权码（不是登录密码）
MAIL_FROM=你的邮箱@qq.com
EOF

sudo chmod 600 /etc/jiuyoumap.env
sudo chown root:root /etc/jiuyoumap.env
```

> **为什么邮件是必须的**：没配 SMTP 时程序处于「开发模式」，会把验证码直接返回给前端——**任何人都能登录任意邮箱**。配好后这个后门自动关闭。
> QQ 邮箱：设置 → 账户 → 开启 SMTP 服务 → 生成「授权码」当密码用。
> 也可以用企业邮箱、阿里云邮件推送、腾讯云 SES 的 SMTP 账号。

## 4. 常驻服务

```bash
sudo cp deploy/jiuyoumap.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now jiuyoumap
systemctl status jiuyoumap --no-pager
journalctl -u jiuyoumap -n 30 --no-pager
```

启动横幅会打印：
- 底图是否已配置
- **邮件是否已配置**（生产环境没配会打警告）
- 数据库路径

## 5. 域名 + HTTPS

1. 域名 A 记录指向服务器 IP；
2. 改 `deploy/Caddyfile` 里的 `your-domain.com`；
3. 安装配置：

```bash
sudo cp deploy/Caddyfile /etc/caddy/Caddyfile
sudo systemctl reload caddy
journalctl -u caddy -n 30 --no-pager   # 看到 certificate obtained 就成功
```

Caddy 会自动申请并续期证书，也会给 `/api/stream` 关掉缓冲（SSE 必需）。

验证：

```bash
curl -I https://your-domain.com/
curl https://your-domain.com/api/health
```

## 6. 初始化管理员

1. 用你的邮箱在网站上注册；
2. 提升为站长：

```bash
cd /opt/jiuyoumap
sudo -u jiuyoumap /usr/bin/node scripts/admin.mjs promote 你的邮箱@example.com
sudo -u jiuyoumap /usr/bin/node scripts/admin.mjs list
```

3. 打开 `https://your-domain.com/admin`。

## 7. 备份（务必做）

SQLite 单文件，备份极其简单：

```bash
# 手动备份
cd /opt/jiuyoumap && sudo -u jiuyoumap /usr/bin/node scripts/backup.mjs backups

# 每天 4:10 自动备份，保留 14 天
sudo crontab -u jiuyoumap -e
10 4 * * * cd /opt/jiuyoumap && /usr/bin/node scripts/backup.mjs backups && find backups -name 'app-*.db' -mtime +14 -delete
```

**恢复**：停服务 → 把备份文件覆盖回 `data/app.db`（同时删掉 `app.db-wal`、`app.db-shm`）→ 启动。

建议每周把 `backups/` 同步一份到对象存储或自己电脑（`scp`/`rclone`）。

## 8. 监控

- **存活**：外部拨测 `https://your-domain.com/api/health`（UptimeRobot / 腾讯云监控，1 分钟一次即可）
- **日志**：`journalctl -u jiuyoumap -f`，Caddy 日志在 `/var/log/caddy/jiuyoumap.log`
- **磁盘**：SQLite 很小，但如果有人传图要留意
- **慢查询**：点位量级上万后，`/api/map/feed` 会变慢，届时再做服务端聚合

## 9. 合规清单（逐条打勾）

- [ ] **ICP 备案**（境内服务器）或明确选择境外
- [ ] **公安联网备案**（境内上线后 30 天内）
- [ ] 页脚展示：非官方声明 + ICP 备案号 + 举报邮箱
- [ ] 《用户协议》《隐私政策》《个人信息收集与用途清单》《免责声明》《社区规范》可在站内打开（`/legal/*`）
- [ ] 登录页的「单独同意」未被去掉（位置 / UID / 14 周岁）
- [ ] 底图是天地图且有**审图号署名**（页脚）
- [ ] 点位限制在中国境内（服务端已校验）
- [ ] 举报入口可用，且有人处理（管理员是你自己，别失踪）
- [ ] 未成年人保护：14 周岁确认 + 举报通道
- [ ] 数据出境：确认没有把用户数据发到境外服务（天气若用 Open-Meteo 属于境外，**建议换和风天气**）

## 10. 天气服务换境内

Open-Meteo 是境外服务。上线建议换和风天气：

1. 注册 https://dev.qweather.com/ ，创建「Web API」Key；
2. 改 `server/weather.js` 里的请求地址为 `https://devapi.qweather.com/v7/weather/now?location=<lng>,<lat>&key=...`
3. 在《个人信息收集与用途清单》里把天气服务商改成和风。

这一步不做也能跑，但隐私政策里必须如实写「天气数据经境外服务商」。

## 11. 更新流程（以后改代码）

```bash
cd /opt/jiuyoumap
sudo -u jiuyoumap git pull
sudo systemctl restart jiuyoumap
sudo systemctl status jiuyoumap --no-pager
```

静态文件（`public/`）刷新即生效，**不需要重启**；改了 `server/` 才需要 restart。

## 12. 回滚

- 代码：`git reset --hard <上一个 commit>` + restart
- 数据：停服务 → 覆盖 `data/app.db` → 启动
- 数据库结构变更前**先备份**（本项目用 `CREATE TABLE IF NOT EXISTS`，不会自动迁移）

## 附：常见问题

**打不开 / 502**：`systemctl status jiuyoumap`；多半是 `HOST` 没设成 127.0.0.1 或端口被占。

**证书申请失败**：域名没解析到本机 / 80 端口被封。Caddy 需要 80 端口做 ACME 验证。

**收不到验证码**：看 `journalctl` 有没有 `[mail] ... 已发送`；有就是进了垃圾箱，需要配置 SPF/DKIM（企业邮箱一般都有）。

**地图空白**：`TDT_TK` 没配或配错；浏览器控制台会看到天地图 403。

**登录后刷新就退出**：确认没有用 IP 直接访问（Cookie 绑域名），以及服务器时间准确。
