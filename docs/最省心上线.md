# 最省心上线：全程浏览器操作，零安装、零维护

> 目标：**不装任何软件、不管服务器、不花钱**，把这个站放到公网上。
> 需要你做的只有：注册两个账号、点几次按钮、粘贴几段文字。

---

## 为什么是 Cloudflare（而不是云主机）

| | Cloudflare Workers + D1 | 云主机（Oracle/学生机） |
|---|---|---|
| 花钱 | ¥0 | ¥0–99/年 |
| 打系统补丁 | 不用 | 要 |
| 配 HTTPS 证书 | 自动 | 要（Caddy 也要配） |
| 扩容 | 自动 | 要手动 |
| 备份 | D1 自带时间点恢复 | 要自己写 cron |
| 机器挂了 | Cloudflare 自己修 | 你要爬起来修 |
| 你本地要装什么 | **什么都不用** | 要 Git、SSH、Node |

**结论**：要"省心"，只有这条路。代码已经适配好了，在 `worker/` 目录。

---

## 第 1 步：把代码放到 GitHub（10 分钟）

详细图文步骤见 **[怎么上传代码.md](怎么上传代码.md)**（含仓库名必须是英文的提醒）。这里是要点：

> ⚠️ 仓库名不能有中文，9友地图 会被截成 9，请改成 jiuyoumap。

1. 打开 https://github.com/new ，仓库名填 `jiuyoumap`，选 **Private**（私有也行，Cloudflare 能读）或 Public，点 Create；
2. 进入仓库，点 **Add file → Upload files**；
3. 把 `E:\9友地图` 下的这些**文件夹和文件**拖进去：
   ```
   server/  worker/  public/  scripts/  docs/  deploy/
   package.json  wrangler.jsonc  README.md  .gitignore
   .github/（可选，用 GitHub Actions 部署才需要）
   ```
   > `data/`、`backups/`、`out/` 不要传（已被 .gitignore 排除，也不该公开）。
4. 底部点 **Commit changes**。

> 文件多的话可以分两三次上传，单次最多 100 个文件。

---

## 第 2 步：注册 Cloudflare（2 分钟）

https://dash.cloudflare.com/sign-up —— 邮箱 + 密码即可，**不需要信用卡**。

---

## 第 3 步：建数据库并建表（5 分钟）

1. 左侧菜单 **Storage & Databases → D1 → Create database**，名字填 `jiuyoumap`；
2. 创建后复制 **Database ID**（一长串 UUID）；
3. 打开仓库里的 `wrangler.jsonc`，把 `REPLACE_WITH_YOUR_D1_ID` 换成这个 ID，提交一次；
4. **建表不用你管**：Worker 第一次收到请求时会自动建表（`ensureSchema`），
   因为建表语句已经打包进 `worker/data-schema.js` 了；
5. 想要一上来就有演示内容：在 `wrangler.jsonc` 的 `vars` 里加一行 `"AUTO_SEED": "1"`，
   首次初始化时会顺带写入 30 个演示账号、40 个点位、4 条公告（只在新库上执行一次）。

> 手动建表仍然可行（D1 → Console → 粘贴 `worker/schema.sql`），只是没必要。

---

## 第 4 步：连仓库，自动部署（5 分钟）

1. 左侧 **Workers & Pages → Create → Workers → Connect to Git**；
2. 选中你刚建的仓库；
3. 构建设置填：

   | 项 | 值 |
   |---|---|
   | Build command | `npm install && node scripts/build-worker-assets.mjs` |
   | Deploy command | `npx wrangler deploy` |
   | Root directory | `/`（默认） |

4. 点 **Deploy**，等 2–3 分钟。

成功后你会拿到一个地址：`https://jiuyoumap.<你的子域>.workers.dev`

> 之后每次你在 GitHub 上改文件（哪怕是网页直接编辑），Cloudflare 都会自动重新部署。**这就是"零维护"的核心。**

---

## 第 5 步：填配置和密钥（3 分钟）

进入 Worker → **Settings**：

**Variables and Secrets**（普通变量）：

| 名称 | 值 |
|---|---|
| `TDT_TK` | 你的天地图 Key（没有就先空着，站点会用纸面底图） |
| `ADMIN_EMAIL` | 你的邮箱（第一次登录后自动成为站长） |

**Secrets**（点 Add，加密存储）：

| 名称 | 值 |
|---|---|
| `SESSION_SECRET` | 随便一串 32 位以上的随机字符（比如连按几次键盘） |
| `RESEND_API_KEY` | 邮件服务密钥（见下） |
| `MAIL_FROM` | 发信地址，如 `9友地图 <no-reply@你的域名>` |

### 邮件怎么弄（必须，否则登录会失败）

1. https://resend.com 注册（免费额度 100 封/天，够用）；
2. 添加并验证你的域名（或者先用它给的测试域名 `onboarding@resend.dev` 跑通）；
3. 创建 API Key，填进上面的 `RESEND_API_KEY`。

> 没配邮件时，请求验证码会返回 `502` 并提示"邮件发送失败"——这是**故意的**，避免出现"谁都能登录任意邮箱"的漏洞。

---

## 第 6 步（可选）：绑自己的域名

Workers → 你的 Worker → **Settings → Domains & Routes → Add → Custom domain**，填域名即可。
域名本身要在 Cloudflare 托管（Nameserver 改过去），证书自动签发。

不绑也能用 `*.workers.dev` 地址，只是名字长一点。

---

## 第 7 步：登录当站长

1. 打开站点，用 `ADMIN_EMAIL` 那个邮箱注册；
2. 因为 `ADMIN_EMAIL` 已配置，**注册后自动就是站长**；
3. 访问 `/admin` 就能发公告、管用户、处理举报。

## 备份（免费额度内自带 + 手动兜底）

- **自动**：D1 有 Time Travel（时间点恢复），控制台 → D1 → 你的库 → **Time travel**，可以回滚到某个时刻（保留天数以官网为准）。
- **手动**（建议每月一次）：控制台 → D1 → 你的库 → **Export** → 下载 `.sql` 文件存到自己电脑。

## 常见问题

**部署失败 `database_id` 无效**
→ `wrangler.jsonc` 里的 ID 没换，或者换错了库。

**页面能开，但没有地图底图**
→ `TDT_TK` 没填。填在 Variables（不是 Secrets）。

**登录报「验证码邮件发送失败」**
→ Resend 没配好，或 `MAIL_FROM` 的域名没验证。看 Workers → Logs 里的 `[mail]` 报错。

**别人落点我刷新才看到**
→ 正常。Worker 版没有实时推送（免费方案的限制），数据是准的，只是界面要刷新。

**想改代码**
→ 直接在 GitHub 网页上编辑文件，提交后 2 分钟自动生效。或者把仓库拉到本地改（需要 Git）。

## 如果你以后想换成自己的服务器

`server/` 目录的 Node 版本一直都在，功能更全（有实时推送）。换过去只要：

```bash
node server/index.js
```

数据和表结构可以直接从 D1 导出来导进去。两条路都留着，不锁定。

## 踩过的坑（都是实测踩出来的，照抄可避免）

**1. 配置文件里的 `vars` 会覆盖控制台变量**

`wrangler.jsonc` 一旦声明了 `vars`，每次 Git 构建部署都会**按文件内容重建**——文件里没写的变量会被删掉。

- 普通变量（`TDT_TK`、`ADMIN_EMAIL`、`MAIL_FROM`）→ **必须写进 `wrangler.jsonc`**
- 密钥（`SESSION_SECRET`、`RESEND_API_KEY`）→ 只能在控制台加，配置文件里不要写

**2. 控制台「Add variable and deploy」会用旧脚本**

在 Settings 里点「Add variable and deploy」时，Cloudflare 用的是**当前脚本快照**，不一定是最新提交。结果就是：代码更新了，但线上一半新一半旧（典型症状：某个新接口 404）。

修法：加完变量后，去 Deployments 里对最新一次 Git 构建点 **Retry build**，或用任意一次提交重新触发构建。

**3. D1 多语句 `exec()` 不可靠**

一次性 `DB.exec(整段 schema)` 在 D1 上可能静默失败。Worker 里改成了**按分号拆成单条 `prepare().run()`**，逐条执行并记录错误（见 `worker/index.js` 的 `runStatements`）。

**4. 首次部署后先看自检页**

`/api/diag` 会告诉你：表建了没有、变量生效没有、密钥是不是还是默认值。

```json
{
  "schemaError": null,
  "tables": ["users", "markers", "..."],
  "hasTdtTk": true,
  "hasMailFrom": true,
  "hasResend": true,
  "sessionSecretIsDefault": false
}
```

**5. Resend 测试发件地址只能发给自己**

`onboarding@resend.dev` 只能发到**注册 Resend 的那个邮箱**。想让别人也能注册，必须在 Resend 里验证自己的域名。

**6. `*.workers.dev` 在中国大陆可能打不开**

用手机 4G（不要连 WiFi）测一下。打不开就绑自己的域名（Cloudflare 托管 + Custom domain），或者换回自备服务器方案。
